# BOSS 直聘 · 批量投递助手

一个 Chrome / Edge 扩展（Manifest V3），把「翻岗位 → 读 JD → 判断合不合适 → 点投递 → 记账」这条重复劳动自动化：硬条件先筛，手填条件再评分，可选接入大模型做语义判断，同公司精确去重，投递记录自动成表。

> 本仓库是**扩展源码**，克隆下来即可加载为「已解压的扩展程序」，无需构建、无依赖、无 `npm install`。

---

## 一、它解决什么

投递的痛点不是「点不动鼠标」，是**判断成本**：一个岗位要不要投，得把 JD 从头读到尾，看专业、看语言、看年限、看公司在招什么。人工读一天下来几十个就到极限，而且越往后判断质量越差。

所以这个工具的设计顺序是「**先排除，再判断，最后才动手**」：

```
硬条件筛除  →  条件评分  →  （可选）大模型语义判断  →  投递  →  记账去重
   不满足       低于阈值         仅在有明确证据时拦截
   直接跳过      不投                  否则放行
```

## 二、功能

| 能力 | 说明 |
| --- | --- |
| **硬条件筛选** | 城市 / 薪资 / 专业 / 编程语言 / 关键词，任一不满足直接跳过，不消耗后续判断 |
| **条件评分** | 目标岗位 + 技能词计算匹配分，低于阈值不投；「海投模式」跳过软筛选但硬条件仍生效 |
| **JD 全文校验** | 逐个点开卡片，滚动读完 JD 全文（以「去 APP 与 BOSS 随时沟通」为截止标记）再判断，避免只看摘要误判 |
| **AI 语义判断**（可选） | 支持 DeepSeek / Kimi / 通义 / 智谱 / 硅基流动 / OpenAI / 混元 / 火山方舟，OpenAI 兼容协议，也可自填地址 |
| **精确去重** | 用 `encryptBrandId` 做公司级去重，同一公司不同 HR 发的重复岗位不会重复投 |
| **节奏控制** | 投递间隔 8–15 秒随机，绝不快速连点；达到上限自动停止 |
| **随时中断** | 页面悬浮面板、扩展弹窗、ESC 键三处都能立即停 |
| **投递记录** | 记录自动成表，可导出 CSV；图标角标显示今日投递数 |

## 三、架构

四个进程各管一件事，边界清晰：

```
┌─────────────────────────── 页面 JS 世界 ───────────────────────────┐
│  page-bridge.js  被动拦截 fetch / XHR 里 joblist.json 的响应        │
│                  → 抽取明文薪资、公司全称、encryptBrandId、         │
│                    城市、学历经验标签、JD 摘要                      │
└──────────────────────────┬────────────────────────────────────────┘
                           │ sessionStorage + postMessage
┌──────────────────────────┴────────────────────────────────────────┐
│  content.js      悬浮面板 UI + 主流程状态机：滚动 / 点开 / 读 JD /   │
│                  条件判断 / 点投递 / 翻页 / 停止                    │
│  bridge-inject.js  把 page-bridge 注入页面主世界                    │
└──────────────────────────┬────────────────────────────────────────┘
                           │ chrome.runtime 消息
┌──────────────────────────┴────────────────────────────────────────┐
│  worker.js       Service Worker：代理大模型调用（绕开页面 CSP，      │
│                  API Key 只留扩展进程）、AI 结果缓存、角标、记录页   │
│  ai-core.js      纯函数模块：prompt 构造 / 响应解析 / 拦放决策        │
└──────────────────────────┬────────────────────────────────────────┘
                           │
                    popup/ + records/  （配置面板、记录表格页）
```

### 几个关键取舍

**1. 不主动发请求，只读页面已经收到的数据**

岗位卡上的薪资做过字体加密，靠正则和 OCR 猜既不准也不稳。`page-bridge.js` 换了个路子：运行在页面自身的 JS 世界，**被动拦截**页面自己发出的 `joblist.json` / `job/detail.json` 响应，从原始 JSON 里取明文薪资、公司 ID、标签。

代价是依赖接口结构（页面改版就要跟），收益是字段从此精确——去重、城市判断、薪资比较全部不再靠猜。

**2. API Key 不落到页面上**

content script 受页面 CSP 约束，跨域请求也在页面上下文里，意味着 Key 会暴露给页面。所以所有大模型调用统一走 Service Worker 代理，Key 只存在扩展进程的 `chrome.storage`。

**3. AI 判断「失败放行」**

`ai-core.js` 是纯函数（不依赖 `chrome.*`，可单独在 Node 里跑测试），它有三条硬底线：

- 只有模型给出「**明确硬性门槛 + 原文证据**」时才拦截，不因主观印象杀岗位；
- 候选档案里没写的项，一律不得推断为「不具备」；
- 解析失败 / 超时 / 未配置 → 退回原规则放行，绝不因为 AI 挂了导致整轮投不出去。

另外做了 AI 结果缓存（按 JD 哈希，TTL 7 天，上限 400 条），翻回看过的岗位不重复烧 token。

**4. 不做简历解析**

早期版本试图读取简历自动生成档案，得出的判断反而更差（推断出来的信息比用户手填的更不可靠），1.11.0 起改为**全部手填**：专业、编程语言、年限、学历由用户明确勾选，工具只做它该做的筛选。

## 四、安装

1. 下载仓库（`Code` → `Download ZIP`）并解压，或 `git clone`；
2. 打开 `chrome://extensions`（Edge 为 `edge://extensions`）；
3. 右上角开启 **开发者模式**；
4. **加载已解压的扩展程序** → 选择含 `manifest.json` 的那一层目录；
5. 回到已打开的 BOSS 页面**刷新**一下，右下角出现青色圆形「投」按钮即成功。

需要 Chrome 88+（MV3）。详细配置与使用见 [使用说明.md](使用说明.md)。

```
├── records/               # 投递记录表格页
├── 使用说明.md / .html    # 完整使用手册
└── MANIFEST.txt           # 发布包清单与 SHA-256
```

## 六、关于合规与边界

写在这里，是为了明确这个工具该被怎么用：

- 只用于**自己账号**的求职效率提升，不做多账号、不做代投、不做数据采集转卖；
- 投递节奏做了 8–15 秒随机间隔，就是为了不给对方服务器制造压力，**不建议调小**；
- 不绕过验证码、不破解风控、不伪造身份信息；遇到平台要求人工确认时由人自己处理；
- 不存储账号密码，记录只存在本地浏览器，可随时导出 / 清空；
- 本仓库公开的目的是展示实现（MV3 多进程通信、主世界注入、prompt 工程与失败降级），**不对使用后果负责**，使用前请自行确认符合目标平台的服务条款。
